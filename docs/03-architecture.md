# 03 · 总体架构与技术选型

## 3.1 总体架构

```
                         ┌──────────────────────────────┐
                         │        浏览器（桌面优先）      │
                         │  考生端 / 管理端（同一 SPA）   │
                         └───────────────┬──────────────┘
                                         │ HTTPS
                         ┌───────────────▼──────────────┐
                         │            Nginx             │
                         │  静态资源 · /api 反向代理 · TLS │
                         └───────┬──────────────┬───────┘
                                 │              │
                    ┌────────────▼───┐   ┌──────▼─────────────┐
                    │  Vue 3 静态产物 │   │ Spring Boot 单体    │
                    │  (dist/ 目录)   │   │  rk-boot :8080     │
                    └────────────────┘   │  ├ rk-api  (MVC)   │
                                         │  ├ rk-service      │
                                         │  ├ rk-repository   │
                                         │  ├ rk-domain       │
                                         │  └ rk-common       │
                                         └───┬────────────┬───┘
                                             │            │
                                ┌────────────▼──┐  ┌──────▼───────┐
                                │   MySQL 8     │  │   Redis 7    │
                                │  业务数据/题库 │  │ 会话/缓存/限流 │
                                └───────────────┘  └──────────────┘

        离线（不在请求链路内）：
        ┌──────────────────────────────┐      ┌────────────────────┐
        │ scripts/generate  造题脚本    │ ───→ │ LLM API（外部）     │
        │  输入：outline_ids + 题型     │      └────────────────────┘
        └───────────────┬──────────────┘
                        │ 产出 JSONL
                        ▼
              ┌──────────────────────┐
              │ 管理端审核工作台      │ ──→ 入库为 PUBLISHED 题目
              └──────────────────────┘
```

**关键边界**：AI 只在**离线链路**（造题脚本）中出现，运行期后端不调用任何 LLM 服务。因此 LLM 服务抖动不会影响线上功能，也无需处理供应商配额与超时。

## 3.2 技术选型与理由

| 层 | 选型 | 版本 | 选择理由 |
| --- | --- | --- | --- |
| 前端框架 | Vue 3 + Vite | 3.5 / 5.x | 组合式 API + 编译期优化；Vite 冷启动与热更新快，适合迭代 |
| 前端语言 | TypeScript | 5.x | **AI 协作场景下收益大于人写代码**：编译期报错构成自检回路，把类型错误从运行时提前到构建期 |
| UI 组件库 | Element Plus | 2.x | 管理端重度依赖表格、表单、树、分页、对话框；Element Plus 的中文生态与组件完备度在这四类场景下最省事，避免自造轮子 |
| 状态管理 | Pinia | 2.x | Vue 官方推荐，比 Vuex 更简单的类型推导 |
| 图表 | ECharts | 5.x | 统计模块需要折线/柱状/雷达图，ECharts 覆盖充分 |
| 公式渲染 | KaTeX | 0.16 | 软考题干含大量公式；KaTeX 比 MathJax 渲染快、体积小，且无需在运行时异步加载 |
| 后端语言 | JDK 21 + Spring Boot | 21 / 3.3 | LTS 版本；虚拟线程对 IO 密集型的答题接口有吞吐收益；Boot 3.3 是 3.x 中较稳定的版本 |
| 持久层 | MyBatis-Plus | 3.5 | 单表 CRUD 与分页开箱即用；复杂统计 SQL 可直接写 XML，不被 ORM 抽象绑架 |
| 鉴权 | Sa-Token | 1.39 | **见 ADR-02** |
| 缓存 | Redis | 7.x | **见 ADR-03** |
| 接口文档 | Knife4j (OpenAPI 3) | 4.x | 接口文档覆盖率要求 100%，需要自动生成而非手写 |
| 工具库 | Hutool | 5.8 | 中国开发场景下的常用工具（身份证、日期、集合） |
| 数据库 | MySQL 8.0 | 8.0 | utf8mb4 + 窗口函数（统计模块会用），生态成熟 |
| 容器 | Docker + Compose | — | 部署目标无关（假设 A2），换服务器只改环境变量 |
| CI | GitHub Actions | — | 构建 + 单测 + 镜像推送，最小闭环 |

## 3.3 后端模块划分

### 3.3.1 Maven 模块

```
server/
├── pom.xml                 # 聚合 POM，统一版本管理（dependencyManagement）
├── rk-common/              # 通用能力，无 Spring Web 依赖
│   └── 统一响应体 R<T>、业务异常、错误码枚举、常量、工具类、分页 DTO
├── rk-domain/              # 领域模型，纯 POJO + 枚举，无持久化依赖
│   └── entity / dto / vo / enums（QuestionStatus、QuestionType…）
├── rk-repository/          # 持久层
│   └── mapper（MyBatis-Plus）、XML、Redis DAO、缓存 Key 定义
├── rk-service/             # 业务逻辑，事务边界所在层
│   └── question / practice / exam / stats / review / user 六个业务包
├── rk-api/                 # 对外接口
│   └── controller（portal /admin 分包）、拦截器、全局异常处理、Knife4j 配置
└── rk-boot/                # 启动模块：application.yml、装配、打包为可执行 jar
```

依赖方向单向：`rk-boot → rk-api → rk-service → rk-repository → rk-domain → rk-common`。

### 3.3.2 包结构（以 rk-service 为例）

```
com.ruankao.service
├── question/       # 题目查询、组卷取数
├── practice/       # 练习会话、答题提交、进度
├── exam/           # 模拟考：组卷、计时、交卷判分
├── stats/          # 掌握度、统计聚合
├── review/         # 审核工作台、生成批次
├── user/           # 注册登录、错题本、收藏
└── audit/          # 高危操作留痕（AC-2）；横切能力，不属任何业务域
```

> `audit` 是上表六个业务域之外的第七个包：留痕是被**所有**业务域调用的一件事（P2 的科目停用，将来的题目下架、用户禁用、配置修改）。放进任一业务包都会让其它包为记一条日志而依赖它，而那是一条没有业务含义的假依赖。

每个业务包内统一采用 `XxxService`（接口）+ `impl/XxxServiceImpl` + `XxxConverter`（实体 ↔ VO 转换）三层结构。**不引入 MapStruct**：转换逻辑简单，手写转换器更透明且零构建期成本。

> 决策与理由
> 备选方案是按业务域拆模块（`rk-question`、`rk-exam`…）。选分层拆模块的原因是：按业务域拆会在"考试需要题目、题目需要统计"这类交叉引用上很快产生循环依赖，需要在模块间加接口层来打破，复杂度陡增；而本项目单模块代码量不大（预计 service 层 6 个包、30 个类左右），分层拆模块的编译隔离收益已经足够。**若未来单模块超过 200 个类，再按业务域二次拆分。**

## 3.4 前端工程结构

单 Vue 工程，通过目录与路由前缀隔离两端，管理端代码**不进考生端首屏**。

```
web/src/
├── api/                    # 接口封装，按域拆文件（question.ts、exam.ts…）
├── assets/                 # 静态资源
├── components/             # 通用组件
│   ├── base/               # 无业务：Markdown 渲染、KaTeX、空状态、分页
│   └── question/           # 业务组件：单选题卡、主观题作答框、论文写作框、答题卡
├── layouts/                # PortalLayout / AdminLayout / BlankLayout（登录注册、模拟考答题页，无导航防误触）
├── router/
│   ├── index.ts
│   ├── portal.routes.ts    # 考生端路由
│   └── admin.routes.ts     # 管理端路由（懒加载 + 权限守卫）
├── stores/                 # Pinia：user、practice、exam、subject
├── styles/                 # 变量、重置、主题
├── types/                  # 接口类型定义：api.d.ts（手写，与 05 严格一致）、domain.d.ts（枚举联合类型）
├── utils/                  # request.ts（axios 封装）、format.ts、storage.ts
├── views/
│   ├── portal/             # 考生端页面
│   └── admin/              # 管理端页面
├── App.vue
└── main.ts
```

（对应评审 D7：补齐 `types/` 与 `BlankLayout.vue`，与 [07-frontend.md](07-frontend.md#72-工程结构) §7.2 声明一致。）

> 决策与理由
> 备选方案是"两个独立 Vue 工程"（`web` + `admin`）。放弃的原因：两者要共享接口类型、Markdown/KaTeX 渲染组件、请求封装与常量，分仓会导致这些代码复制两份或抽出私有包；同时构建、依赖升级、部署配置都要做两遍。单工程方案下，`/admin/*` 路由全部动态 `import()`，管理端代码会被 Vite 独立分包，考生端首屏不加载，隔离目标已经达成。

## 3.5 部署拓扑与环境

| 环境 | 组成 | 说明 |
| --- | --- | --- |
| `local` | Docker 起 MySQL + Redis，前后端本地进程 | 日常开发 |
| `prod` | 单机 Compose：`nginx` + `server` + `mysql` + `redis` | 假设 A1；Nginx 同时托管前端静态产物 |

关键环境变量（完整清单见 [09-deployment.md](09-deployment.md)）：

```
MYSQL_HOST / MYSQL_PORT / MYSQL_DATABASE / MYSQL_USERNAME / MYSQL_PASSWORD
REDIS_HOST / REDIS_PORT / REDIS_PASSWORD
RK_TOKEN_TIMEOUT / RK_SERVER_PORT / RK_MGMT_PORT / RK_ACTUATOR_ENABLED
RK_LOG_LEVEL / RK_LOG_DIR / RK_UPLOAD_DIR / RK_CORS_ORIGINS
RK_DOC_ENABLED
```

> **没有令牌签名密钥**：鉴权采用 Sa-Token 的不透明令牌（`token-style: uuid`），登录态存在 Redis，因此不存在 `RK_JWT_SECRET` 这类需要保管与轮换的签名密钥（见 [06-backend.md](06-backend.md#65-鉴权与拦截)）。这是选 Sa-Token 而非 JWT 的附带收益之一。

**硬约束**：代码中不允许出现硬编码的域名、IP、端口、密钥；全部经环境变量注入。

## 3.6 ADR 决策记录

### ADR-01 采单体分层架构，不采微服务

- **决策**：单体 + Maven 分层多模块。
- **理由**：单机部署、50 并发目标、单团队。微服务会引入注册中心、配置中心、网关、链路追踪这一整套运维面，而收益（独立伸缩、独立部署）在此场景下完全用不到。**在单机低并发场景下，微服务是纯负资产。**
- **代价**：无法按模块独立扩容；单进程故障影响全站。**接受**。

### ADR-02 鉴权选 Sa-Token，不选 Spring Security

- **决策**：Sa-Token + Redis 会话。
- **理由**：Spring Security 的过滤器链、CSRF、CORS、`AuthenticationManager` 组合配置在 AI 生成代码时**极易产出"看起来对但认证被绕过"的实现**，且错误通常是静默的（返回 200 而非 401），排查成本极高。Sa-Token 的 `@SaCheckLogin` 注解式校验出错面小一个数量级，中文文档与本项目技术栈同源。
- **代价**：社区与生态弱于 Spring Security，未来若需 OAuth2 多协议支持需要自行扩展。**接受**（本项目的登录方式只有用户名密码）。
- **强制要求**：所有非公开接口必须显式标注 `@SaCheckLogin` 或 `@SaCheckRole("ADMIN")`；`rk-api` 模块加一条单元测试，扫描全部 Controller 方法，未标注鉴权注解且不在白名单内的直接测试失败。**不允许依赖"全局拦截器兜底"这种隐式安全。**
- **强制要求（白名单语义）**：鉴权白名单**只表达「路径级放行」，不得用它表达「按参数放行」**。需要按参数放行的接口（典型是 `POST /api/v1/practice/papers` 的 `mode=SAMPLE` 游客场景）必须标 `@SaIgnore` 并在**方法内**校验参数（`mode=SAMPLE && count≤5`，否则抛 `2005`）；一旦把该路径写进白名单，游客即可用 `mode=FULL` 绕过限制形成安全洞（对应评审 B6，与 [05-api.md](05-api.md#513-鉴权白名单) §5.13 同步）。

### ADR-03 引入 Redis

- **决策**：使用 Redis 7。
- **理由**：至少四类数据天然属于 Redis —— ① Sa-Token 会话（需要 TTL 与强制下线）；② 模拟考会话状态与场次状态（需 TTL 与强制下线）—— 剩余时长是**派生值**而非 Redis 增量值（真值由 `exam_session_sitting.started_at` 派生，Redis 只承载会话与短锁，对应评审 A1）；③ 热点数据缓存（科目、大纲树、卷面模板，几乎不变但每次请求都读）；④ 登录失败计数与接口限流。
- **代价**：多一个需要运维的组件，且断开时需降级。**降级策略**：缓存类数据在 Redis 不可用时回落直查 MySQL；会话类数据不可降级（登录态必须有状态），Redis 不可用时直接拒绝登录并返回明确错误。

### ADR-04 卷面模板驱动，不硬编码试卷结构

- **决策**：模板 / 场次 / 分节**三张表**（`exam_paper_template` + `exam_paper_sitting` + `exam_paper_section`）+ 管理端配置页。（对应评审 G6：原文写"两张表"，未回填 A5 新增的场次表。）
- **理由**：20 个科目分属 2 种卷面类型，且分节题数、分值、时长尚未逐一核实。硬编码意味着每加一个科目就要改代码发版；模板驱动则一次开发、全科目复用，并允许管理员在发现配置错误时自行修正。
- **代价**：需要维护配置数据的正确性（初始化 SQL 需逐科目核对）。**接受**，且这是**唯一**能支撑"全科目覆盖"的做法。

### ADR-05 章节树 + 知识点标签双维度（见 02 文档 2.3）

- **决策**：两者都建，知识点保持扁平不做层级。

### ADR-06 主观题不判分（见 02 文档 2.2.1 / 2.4.3）

- **决策**：`SUBJECTIVE` / `ESSAY` 只展示参考答案与评分要点，不产出任何分数。

### ADR-07 AI 只用于离线造题，且输入不含真题

- **决策**：造题脚本离线执行；输入只有考点与题型（护栏 GR-1）。运行期零 AI 依赖。
- **理由**：① 线上功能不被外部服务稳定性绑架；② 从架构上切断"用真题洗稿"的可能性 —— 脚本运行环境中不存在真题数据，就不可能把它作为输入。
- **代价**：无法做"AI 答疑"这类互动功能。**接受**（见范围外 OOS-03）。

### ADR-08 非商业运营并内置投诉下架通道

- **决策**：全站无付费、无广告；提供版权投诉入口；管理员可一键下架。
- **理由**：非商业性可显著降低侵权认定中的主观恶意与赔偿基数；投诉下架通道是"通知—删除"规则下的合理避风港动作。

## 3.7 容量与资源估算

> 数据量口径以 [04-database.md](04-database.md#49-容量与索引策略) §4.9 为**唯一出处**（对应评审 A4）；本表只保留架构侧的内存与磁盘估算，不另立一套数字。

| 项 | 估算 | 依据 |
| --- | --- | --- |
| 题目数据量 | ≤ 5000 条（3 科 × 250 + 17 科 × 40 ≈ 1430 条，预留约 3 倍冗余至 5000 条） | 04 §4.9（对应评审 A4 / D1） |
| 单题平均体积 | ~3KB（含 Markdown、图片外链） | 题目表数据量 < 20MB |
| 答题记录 | ≤ 400 万条/年 | 04 §4.9（对应评审 A4） |
| 试卷快照 | 每次模拟考 75~85 条快照 | 用户量低，无压力 |
| JVM 内存 | `-Xmx1024m` | 2C4G 单机，MySQL 约占 1G，Redis 256M，余量留给系统与 Nginx |
| 磁盘 | 40GB 起 | 数据库 + 日志 + 镜像；日志按 30 天轮转 |

**性能红线**：请求链路中不允许出现全表扫描的重计算；统计类操作若超过 200ms，改为读时聚合 + Redis 缓存 10 分钟。

## 3.8 关键架构约束汇总

| 编号 | 约束 | 校验方式 |
| --- | --- | --- |
| AC-1 | 业务代码禁止硬编码域名/IP/端口/密钥 | 代码评审 + 启动时校验必需环境变量存在 |
| AC-2 | 高危操作（删题、下架、重置密码）必须记 `sys_operation_log` | 单元测试覆盖 |
| AC-3 | 用户数据访问必须带 `user_id` 条件，禁止仅凭前端传入的 ID 直查 | Service 层入参强制携带当前登录用户 ID |
| AC-4 | **所有列表查询必须保证结果集有上界**：常规列表一律分页；枚举型全量接口（如科目列表，上界 = 科目总数，[05 §5.4](05-api.md)）可不分页，但 SQL 仍必须带一条防御性 `LIMIT` | Mapper 层禁止"无分页且无 `limit`"的查询（代码评审项） |
| AC-5 | 只有 `PUBLISHED` 状态的题目可被组卷 | 组卷查询条件强制包含状态过滤，单测覆盖 |
