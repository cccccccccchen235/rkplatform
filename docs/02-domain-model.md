## 2.1 软考考试体系

### 2.1.1 考试制度事实（2026 年度）

## 2.2 题型模型

### 2.2.1 题型枚举

| 枚举值 | 名称 | 判分方式 | 出现场景 | 状态 |
| --- | --- | --- | --- | --- |
| `SINGLE_CHOICE` | 单选题 | 自动判分（严格相等），答对得分，答错/未答 0 分 | 初/中级「基础知识」、高级「综合知识」（均为 75 题单选） | **主力，唯一默认生成题型** |
| `MULTI_CHOICE` | 多选题 | 自动判分（集合完全相等才得分，不给部分分） | 预留 | 模型支持，**生成流水线默认不产出** |
| `TRUE_FALSE` | 判断题 | 自动判分 | 预留 | 模型支持，**生成流水线默认不产出** |
| `SUBJECTIVE` | 主观题 | **不判分**，展示参考答案与评分要点 | 初/中级「应用技术」、高级「案例分析」 | 实现 |
| `ESSAY` | 论文 | **不判分**，提供计时写作框、实时字数统计、参考答案、导出 | 高级「论文」 | 实现 |

> 决策与理由
> 官方的客观题全部是单选题，`MULTI_CHOICE` / `TRUE_FALSE` 是模型层的预留而非产品需求。之所以仍然放进枚举，是因为判分引擎对三者的实现是同一段代码路径（仅比较逻辑不同），保留可避免未来改表；但生成流水线默认只产出 `SINGLE_CHOICE`，防止出现"官方不考的题型"污染题库可信度。
>
> `SUBJECTIVE` 与 `ESSAY` **绝不判分、不做自评打分**。理由是：判分准确性无法保证，而让用户自评打分只会产生一个无人信任的假分数。产品的处理是"展示参考答案 + 明确标注不计分"，成绩页把客观题得分与主观题内容分区呈现。

### 2.2.2 题目内容结构约定

| 字段 | 说明 |
| --- | --- |
| `stem` | 题干，Markdown 文本，支持 KaTeX 行内公式 `$...$` 与块级公式 `$$...$$` |
| `stem_format` | `MARKDOWN`（唯一值，预留 `HTML` 扩展位） |
| `options` | 选项列表，仅客观题有值；每项 `{key: "A", content: "Markdown"}`，key 为 A~F 大写字母 |
| `correct_answer` | 客观题填选项 key（多选按字典序拼接，如 `"ABD"`）；主观题填 `NULL` |
| `reference_answer` | 主观题/论文的参考答案正文（Markdown）；客观题可为空 |
| `analysis` | 解析，Markdown，支持插图 |
| `score_points` | 主观题评分要点，JSON 数组，如 `["能说明数据流图的四个要素", "..."]` |
| `difficulty` | 难度 1~5 整数（1 最易），用于组卷配比与统计 |
| `images` | 题目引用的图片列表，JSON 数组，元素含 `url`、`alt` |

**公式与图片的必要性**：软考题干包含大量计算（如指令流水线、CRC、周转时间）与图形（UML 图、数据流图、网络拓扑）。因此题干必须是 Markdown + KaTeX + 图片的三件套，纯文本字段会直接导致大量题目无法录入。

## 2.3 大纲与知识点

题目按两个**正交**维度组织，缺一不可：

### 维度一：大纲章节树（`rk_outline_node`）

- 自引用树，最多 3 层：`level ∈ {1, 2, 3}`（如 `计算机系统基础知识 → 操作系统 → 进程管理`）。
- 严格取自官方考试大纲的**章节标题**，挂在科目下。
- 题目直接挂**叶子章节**（`rk_question.outline_id` 指向 level=3 节点；若某学科只有 2 层则为 leaf）。
- 用途：学习进度、树形浏览、按章节组卷、章节掌握度。

### 维度二：知识点标签（`rk_knowledge_point`）

- 扁平标签，多对多挂到题目（`rk_question_kp`），单题 1~5 个标签。
- 标签由 AI 生成时标注 + 人工在审核台校正，允许同义标签合并（保留 `aliases`）。
- 用途：薄弱点画像、跨章节横向练习、知识点维度统计。

> 决策与理由
> 只用章节树 → 统计只能输出"第 3 章正确率 60%"，用户无法知道到底哪里弱；只用知识点 → 与官方大纲脱节，无法做"按章学习"的进度感。二者正交且用途不可互相替代，因此两者都要。
> 成本控制：知识点标签**不做层级**（不做树），保持扁平 —— 层级化标签会让标注与维护成本翻倍，而统计收益很小。

### 大纲数据边界（版权相关）

| 允许 | 禁止 |
| --- | --- |
| 使用官方大纲的**章节标题**作为事实性索引（标题短语、功能性信息） | 复制大纲正文的描述性内容 |
| 自行归纳的层级组织与排序 | 复制"掌握 / 熟悉 / 了解"分级条目原文 |
| 在后台让管理员手工补录章节 | 整本转载官方大纲 |

字段 `rk_outline_node.origin` 记录来源：`OFFICIAL_TITLE`（取自官方大纲标题）/ `MANUAL`（人工归纳），便于审计。

## 2.4 卷面模型（场次 + 分节两层结构）

卷面由**模板驱动**：后台为每个科目配置一份模板，模板下挂若干**场次（sitting）**，每个场次下挂若干**分节（section）**。组卷引擎只认模板，不认科目，因此新增科目无需改代码。

### 2.4.1 为什么必须分两层：场次（sitting）

真实机考的时长不是"一条连续倒计时"：

| 级别 | 场次划分 | 事实依据 |
| --- | --- | --- |
| 初级、中级 | **1 个场次**：基础知识 + 应用技术**连考**，作答总时长 240 分钟；基础知识最长 120 / 最短 90 分钟，节余时长自动可用于应用技术 | 连考科目共享总时长 |
| 高级 | **2 个场次**：场次一 = 综合知识 + 案例分析连考，总时长 240 分钟（综合知识最长 150 / 最短 120）；场次二 = 论文独立 120 分钟，**不得提前交卷** | 官方批次安排中论文在下午独立时段（如 14:30—16:30），与上午的连考场次之间**隔着午休** |

关键推论：**场次之间不能连续倒计时** —— 午休期间不该扣论文的时间。因此每个场次有**独立的时长与独立的 `started_at`**，且**场次二由用户主动开始**（点"开始论文"才启动计时），而不是交完场次一自动开始。

> 决策与理由（对应评审 A5）
> 早期设计把一份试卷建模为"一个会话 + 一条连续倒计时"，无法表达高级的两场次结构。评审提出的修法是"论文并入连考、总时长 360 分钟"，但这**与事实不符**：论文是下午的独立场次，中间隔着午休，按 360 分钟连续计时会让考生在午休时被扣掉 120 分钟。正确解法是引入 `sitting_no`，**每个场次各有一条独立倒计时，场次之间不自动衔接**。

### 2.4.2 模板类型与场次构成

| 类型 | 适用级别 | 场次 | 分节构成 |
| --- | --- | --- | --- |
| `JUNIOR_MID` | 初级、中级 | 场次 1，`total_duration` = 240 | ① 基础知识 `SINGLE_CHOICE` × 75（75 分），时长 90~120 分钟<br>② 应用技术 `SUBJECTIVE` × 5（75 分），时长 120~150 分钟 |
| `SENIOR` | 高级 | 场次 1，`total_duration` = 240 | ① 综合知识 `SINGLE_CHOICE` × 75（75 分），时长 120~150 分钟<br>② 案例分析 `SUBJECTIVE` × 3（75 分），时长 90~120 分钟 |
| `SENIOR` | 高级 | 场次 2，`total_duration` = 120 | ③ 论文 `ESSAY` × 1（75 分），时长 120~120 分钟，`allow_early_submit = false` |

**场次内总时长共享**：同一场次的所有分节共享该场次的 `total_duration`；分节的 `duration_min` / `duration_max` 只约束**该节最早可离开 / 最晚可离开**的时间点。因此两者必须与场次总时长自洽：

```
Σ(duration_min) ≤ sitting.total_duration ≤ Σ(duration_max)
```

上述蓝图均满足：初级/中级 `90 + 120 = 210 ≤ 240 ≤ 120 + 150 = 270`；高级场次一 `120 + 90 = 210 ≤ 240 ≤ 150 + 120 = 270`；论文场次 `120 ≤ 120 ≤ 120`。

### 2.4.3 分节字段

| 字段 | 说明 |
| --- | --- |
| `sitting_no` | 所属场次（1 / 2） |
| `section_type` | `OBJECTIVE` / `SUBJECTIVE` / `ESSAY` |
| `question_count` | 本节题数 |
| `per_question_score` | 每题分值（客观题 1 分，主观题按题给分） |
| `duration_min` / `duration_max` | 本节**最早可离开 / 最晚可离开**的时间点（分钟），**两者均为必填** |
| `allow_early_submit` | 是否允许提前交卷离场；论文节为 `false` |
| `support_status` | `SUPPORTED` / `NOT_SUPPORTED`；信息处理技术员的「应用技术」为 `NOT_SUPPORTED` |

**离开本节的门槛规则（唯一一条）**：必须 `usedSec >= duration_min` 才能离开本节；若 `usedSec` 已达到 `duration_max`，则强制离开（进入下一节，或结束场次）。

> 决策与理由（对应评审 A6 与 B11）
> ① `duration_min` / `duration_max` **一律必填**。早期只在 `allow_carry_over = true` 时才要求填 `duration_max`，导致案例分析节"何时能进下一节"这个门槛值缺失、逻辑上不可计算。
> ② **删除 `allow_carry_over` 字段**（连同 API 的 `carryOver` 请求参数与前端勾选框）。在"场次内总时长共享"的模型下，节余时长自动可用，该字段既不是判定依据也无法配置，属纯冗余，按 YAGNI 删除。

### 2.4.4 分数口径（重要）

| 口径 | 定义 | 展示方式 |
| --- | --- | --- |
| `total_max_score` | 模板所有**场次**分值之和（`NOT_SUPPORTED` 分节不计） | 成绩页显示为"卷面满分" |
| `auto_scored_max_score` | 仅 `OBJECTIVE` 分节分值之和 | 成绩页显示为"可判分满分" |
| `objective_score` | 用户客观题实际得分 | **唯一参与"是否通过"判定的分数** |
| 主观题 | 不计分 | 单独分区展示"参考答案与评分要点"，明确标注"本节不判分" |

场次级同样带 `total_max_score` / `auto_scored_max_score`（用于成绩页按场次分区展示），模板级为各场次之和。

> 决策与理由
> 不编造主观题分数。若把主观题按"参与率"折算成假分数，成绩页会给出一个无法解释的数字，反而降低工具可信度。明确区分"可判分满分"与"卷面满分"，并注明"官方评分由阅卷组人工完成"，是唯一诚实的做法。
> `NOT_SUPPORTED` 分节的处理：前台显示该节的题型说明与"本平台无法模拟 Office 操作题，请前往官方机考模拟练习平台"的提示，**不参与组卷、不计入任何满分口径**。

## 2.5 状态机

### 2.5.1 题目状态（`rk_question.status`）

```
                  ┌──────────────┐
   （新建/导入） →  │    DRAFT     │
                  └──────┬───────┘
                         │ 提交审核
                         ▼
                  ┌──────────────┐   驳回   ┌────────────┐
                  │PENDING_REVIEW│ ───────→ │  REJECTED  │
                  └──────┬───────┘          └─────┬──────┘
                         │ 审核通过                │ 退回重生成（重新进入 DRAFT）
                         ▼                        └──→ DRAFT
                  ┌──────────────┐
                  │   APPROVED   │
                  └──────┬───────┘
                         │ 发布
                         ▼
                  ┌──────────────┐   下架   ┌────────────┐
                  │  PUBLISHED   │ ───────→ │  OFFLINE   │
                  └──────────────┘          └────────────┘
```

| 状态 | 可被组卷 | 说明 |
| --- | :-: | --- |
| `DRAFT` | ✗ | 新建或退回重生成后的编辑态 |
| `PENDING_REVIEW` | ✗ | 等待人工审核 |
| `APPROVED` | ✗ | 审核通过，仅管理员可见 |
| `REJECTED` | ✗ | 驳回，需修改后重新提交 |
| `PUBLISHED` | **✓** | 已发布，唯一可被组卷的状态 |
| `OFFLINE` | ✗ | 下架，保留历史作答记录 |

> 决策与理由
> 台账中的 `AI_GENERATED → PENDING_REVIEW` 把"来源"与"工作流状态"混在一个字段里，实现时拆成两个字段：`source_type`（数据来源，审计用）与 `status`（工作流状态，控制可见性）。原因：一个手工录入的原创题同样需要走审核流程，而一道 AI 生成的题被驳回修改后，其"来源"依然是 AI_GENERATED —— 合并字段会让这两种信息互相覆盖。
> `source_type` 取值：`AI_GENERATED` / `ORIGINAL`（人工原创）/ `LICENSED`（已获授权）。**必填、不可为空**（对应约束 C1）。

### 2.5.2 模拟考会话状态（`exam_session.status`）

| 状态 | 说明 | 后继 |
| --- | --- | --- |
| `CREATED` | 试卷快照已生成，尚未开始作答 | `IN_PROGRESS` / `ABANDONED` |
| `IN_PROGRESS` | 作答中，服务端计时 | `SUBMITTED`（用户交卷） / `SUBMITTED`（超时自动交卷） |
| `SUBMITTED` | 已交卷，不可再作答 | `SCORED` |
| `SCORED` | 已判分完成 | 终态 |
| `ABANDONED` | 用户主动放弃，不计入成绩统计 | 终态 |

### 2.5.3 生成批次状态（`rk_generation_batch.status`）

| 状态 | 说明 |
| --- | --- |
| `PENDING` | 批次已创建，未执行 |
| `GENERATING` | 生成中（离线脚本执行） |
| `GENERATED` | 产出已入库为 `DRAFT`，等待审核 |
| `REVIEWING` | 审核进行中 |
| `COMPLETED` | 全部题目已裁决（通过或驳回） |
| `FAILED` | 生成失败（记录失败原因） |

### 2.5.4 练习进度（`user_practice_progress`）

顺序练习按「用户 × 科目 × 练习类型」记录游标，用于"继续上次练习"。

### 2.5.5 场次状态（`exam_session_sitting.status`）

```
PENDING ──用户点"开始本节次"──→ IN_PROGRESS ──时长耗尽/用户结束/最后一节交卷──→ FINISHED
```

| 状态 | 计时 | 说明 |
| --- | --- | --- |
| `PENDING` | **未启动** | 场次尚未开始，`started_at` 为空，**不倒计时**。这是午休/换场的状态 |
| `IN_PROGRESS` | 运行中 | `started_at` 已写入，`remainingSec = max(0, total_duration_sec - (now - startedAt))` |
| `FINISHED` | 已停止 | 终态，不可再作答；`remaining_sec` 冻结为 `0` |

会话（`exam_session`）的状态不变（`CREATED/IN_PROGRESS/SUBMITTED/SCORED/ABANDONED`）：两份场次都属于同一个会话，会话在全部场次 `FINISHED` 之后才 `SUBMITTED`。**唯一例外**：论文场次若被用户放弃（不点"开始论文"直接交卷），则论文场次置 `FINISHED` 且不生成作答，成绩页标注"论文未作答"。

### 2.5.6 分节状态（`exam_session_section.status`）

本节是分节状态的**权威定义处**（对应评审 G5：此前该枚举只零散出现在 05 的 `SectionVO.status` 与 06 的成绩页逻辑里，而本文件是 02/05/06/08 共同认定的权威定义处，唯独缺了分节）。

| 状态 | 含义 | 进入条件 |
| --- | --- | --- |
| `PENDING` | 未开始 | 创建会话时的初始值 |
| `IN_PROGRESS` | 作答中 | 所属场次 `IN_PROGRESS` 且该分节为 `current_section_no` |
| `FINISHED` | 已结束 | 用户离开本节（`usedSec >= duration_min`）或该节 `duration_max` 到达被强制离开 |
| `SKIPPED` | 不参与作答 | `support_status = 'NOT_SUPPORTED'`（Office 操作题）——创建会话时直接置为该状态，**不生成 item、不计分**，成绩页原样展示"本平台无法模拟" |

离开本节的门槛规则见 §2.4.3；场次状态见 §2.5.5。**分节状态不独立计时**——计时完全由所属场次的 `started_at` 决定（§2.4.1）。

## 2.6 版权与数据来源策略

本节是硬约束，任何绕过此约束的实现均视为严重缺陷。

### 2.6.1 三条护栏

| 编号 | 护栏 | 强制方式 |
| --- | --- | --- |
| GR-1 | **生成流水线的输入只能是大纲考点与题型模板**，禁止读取任何真题原文 | `scripts/generate/` 的生成入口只接受 `outline_ids[]`、`question_type`、`count`、`difficulty`、`prompt_version` 参数；脚本运行目录中不存在真题文件；调用 LLM 前对 Prompt 做"真题特征词"断言校验（如出现"历年真题""20XX 年上半年试题"等片段直接中止），并有单测覆盖 |
| GR-2 | **全链路来源留痕** | `rk_question.source_type` / `source_ref` / `source_license` / `generation_batch_id` 四字段必填或强制关联；`rk_question_review_log` 记录每次状态流转的操作人与时间 |
| GR-3 | **非商业 + 可投诉下架** | 全站不出现付费、会员、广告入口；页脚声明数据来源与版权立场；提供 `/feedback` 侵权投诉入口，管理员可在管理端一键下架题目（`PUBLISHED → OFFLINE`） |

### 2.6.2 允许 / 禁止清单

| ✅ 允许 | ❌ 禁止 |
| --- | --- |
| 依据考点与题型结构**独立命制**题目 | 复制真题题干、选项、解析的任何原文 |
| 使用知识点的定义、公式、通用术语 | 对真题做"改写/换数字/换主语"等派生（构成改编） |
| AI 生成后人工审核、署名"本站练习题" | 使用"历年真题""官方原题"等表述 |
| 引用公开标准、开源文档中的通用知识 | 转载真题 PDF、官方教材、大纲正文 |
| 使用开源仓库的**代码/结构**（遵守其 LICENSE） | 使用开源仓库中**题目内容**（仓库作者无权授权） |

### 2.6.3 用户反馈与下架

- 用户可对任意题目提交反馈，类型：`TYPO`（错别字）/ `WRONG_ANSWER`（答案存疑）/ `UNCLEAR_ANALYSIS`（解析不清）/ `COPYRIGHT`（版权投诉）/ `OTHER`。
- `COPYRIGHT` 类型反馈在管理端标记为**最高优先级**，处理动作为下架（`PUBLISHED → OFFLINE`），下架后所有引用该题的试卷快照保留，但题目不再出现在新组卷中。
