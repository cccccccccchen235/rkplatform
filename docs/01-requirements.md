# 01 · 需求基线

> 本文件定义「做什么、不做什么、做到什么程度」。任何后续阶段的临时需求，若不在此文件的功能清单内，必须先更新本文件再实现。

## 1.1 项目目标

| 目标 | 可验证的判定方式 |
| --- | --- |
| G1 建立泛化到 20 个软考科目的内容结构 | 数据库中存在 20 个科目记录，其中 3 个热门科目有完整大纲章节树，其余科目至少存在"科目"记录 |
| G2 完成客观题学习闭环 | 用户可完成"选科目 → 刷题 → 判分 → 错题入库 → 复盘重做 → 查看统计"全流程 |
| G3 还原软考机考体验 | 可按科目卷面模板发起模拟考，含分节、计时、答题卡、断点续答、交卷出分 |
| G4 建立可复用的题库生产能力 | 存在"AI 生成 → 审核 → 发布"闭环，且生成输入不含任何真题原文 |
| G5 全站可在公网访问 | 单机容器化部署后，外网设备可注册、刷题、交卷 |

## 1.2 角色定义

| 角色 | 标识 | 说明 | 权限边界 |
| --- | --- | --- | --- |
| 游客 | `GUEST` | 未登录访问者 | 仅可浏览科目列表、章节结构、部分样例题与解析；不可答题记录、不可模拟考 |
| 注册考生 | `USER` | 已注册登录的备考者 | 全部学习功能；仅可操作**自己的**数据 |
| 管理员 | `ADMIN` | 站点运营者 | 题库管理、审核工作台、科目/大纲/知识点/卷面维护、用户管理；**不可查看用户答卷原文以外的敏感信息**，不可修改已发布题目的作答记录 |

> 角色以 `sys_user.role` 单字段承载（`USER` / `ADMIN`）。**不引入 RBAC 五表模型**：本项目只有两种角色，五表模型是纯粹的复杂度而无收益。若未来需要细粒度权限，在 `sys_user` 上加 `permissions` JSON 列即可。

## 1.3 用例清单

### 游客

| 编号 | 用例 | 说明 |
| --- | --- | --- |
| UC-G01 | 浏览科目列表 | 按级别（初级/中级/高级）分组，见科目所属考试批次、试卷结构摘要 |

## 1.5 非功能需求

| 类别 | 指标 | 说明 |
| --- | --- | --- |
| 性能 | 常规接口 P95 < 300ms，P99 < 1s | 单机部署，不含 AI 生成（离线） |
| 性能 | 组卷一科 75 题 < 800ms | 含防重复过滤与知识点覆盖校验 |
| 并发 | 支撑 50 并发在线用户 | 单机 2C4G 目标；不追求高并发 |
| 容量 | 题目 ≤ 2 万条、答题记录 ≤ 500 万条/年（**设计容量上限**） | 单表不分区，靠索引与冷热分离 |
| 容量 | 阶段一目标量见 [03-architecture.md](03-architecture.md#37-容量与资源估算) §3.7，以 [04-database.md](04-database.md#49-容量与索引策略) §4.9 为唯一出处 | 「设计上限」与「阶段目标」分开表述（对应评审 A4） |
| 可用性 | 月度可用性 ≥ 99% | 单机无冗余，接受计划内维护窗口 |
| 安全 | 密码 BCrypt(strength=10) 存储；接口鉴权 100% 覆盖；登录失败 5 次/15 分钟锁定 | 越权访问必须返回 403 而非 404 |
| 安全 | 所有入参 Jakarta Validation 校验；MyBatis-Plus 参数化查询；富文本内容服务端白名单过滤 | 防 XSS / SQL 注入 |
| 兼容 | Chrome / Edge / Safari 最近两个大版本；布局最小宽度 1280px | **桌面优先**，移动端保证可用不做适配优化 |
| 可维护 | 核心算法（组卷、判分、掌握度、计时）单测覆盖；接口文档覆盖率 100% | 不设全局覆盖率硬指标，避免为指标写无效测试 |
| 可观测 | 结构化 JSON 日志、请求链路 traceId、慢 SQL 日志（>500ms） | 单机场景不引入 ELK，日志落文件 + 轮转 |
| 国际化 | 仅简体中文 | 不引入 i18n 框架 |

## 1.6 范围外清单（Out of Scope）

以下内容**明确不做**，实现阶段不得临时加入：

| 编号 | 不做的事 | 原因 |
| --- | --- | --- |
| OOS-01 | Office 操作题（初级·信息处理技术员"应用技术"） | Web 无法模拟 Word/Excel/PPT 操作环境；该科目试卷分节标记为 `NOT_SUPPORTED`，前台提示去官方机考系统练习 |
| OOS-02 | 主观题自动判分 / AI 批改 | 判分准确性无法保证，且会引入在线 AI 依赖；一律"参考答案 + 用户自评" |
| OOS-03 | 在线 AI 功能（智能答疑、RAG 问答、自适应推荐） | 产品定位为练习工具；AI 仅用于离线造题 |
| OOS-04 | 社区、论坛、评论、点赞、排行榜 | 只增加面积不增加价值，且带来内容审核负担 |
| OOS-05 | 付费、会员、广告、课程售卖 | 商业性会显著提高版权风险；本站非商业运营 |
| OOS-06 | 移动 App、微信小程序、公众号 | 与部署方案（海外单机）冲突，且工期不允许 |
| OOS-07 | 手机号注册、短信验证码、微信/QQ/GitHub 登录 | 需国内企业资质与备案，境外部署场景不可行 |
| OOS-08 | 微服务、分布式、消息队列、分库分表 | 单机低并发，引入即为纯运维负担 |
| OOS-09 | 视频课程、直播、课件下载 | 存储与带宽成本高，版权风险高 |
| OOS-10 | 多语言、深色模式 | 收益低 |
| OOS-11 | 真题原文、真题 PDF、官方教材内容 | 版权风险，见 02 文档版权策略 |

## 1.7 约束与假设

| 类型 | 内容 |
| --- | --- |
| 假设 A1 | 部署形态为**单台 VPS**（预计海外/香港节点 + 域名），MySQL/Redis/后端/前端全部容器化在同机 |
| 假设 A2 | 部署目标无关：所有产物容器化，切换服务器不需改代码，仅改环境变量 |
| 假设 A3 | 无真实用户量要求；验收标准为"公网可访问 + 全流程可走通" |
| 假设 A4 | AI 造题使用外部 LLM API，**离线执行**，运行期不依赖 |
| 约束 C1 | 题库数据必须可追溯到来源类型（AI 生成 / 原创 / 已授权），字段不可为空 |
| 约束 C2 | 生成流水线的输入**只能**是大纲考点与题型模板，技术上禁止读取真题原文 |
| 约束 C3 | 单机资源有限，禁止在请求链路中做重计算；统计类数据允许 T+1 或读时聚合 |
| 约束 C4 | 所有时间以服务端时间为准，客户端时间戳仅作展示与审计参考 |
