## 2. 开工前的两个前置（不解决就会空转）

### 2.1 前置 A · `bash` 不在 PATH —— `22` 的两个断言脚本"照文档跑不了"（🔴 必须先修）

**事实（本轮实测）**。先说清楚**不是"bash 没装"**——bash 装了，而且就在 `D:\Git` 下；问题只在**PATH 里加的是哪一个子目录**：

| 项 | 结果 |
| --- | --- |
| `bash.exe` 在哪 | **`D:\Git\bin\bash.exe` 存在**；`D:\Git\usr\bin\bash.exe` 也存在；`D:\Git\git-bash.exe`（双击用的启动器）在根目录 |
| PATH 里含 `Git` 的条目 | **只有一条：`D:\Git\cmd`** |
| `D:\Git\cmd` 里有什么 | 11 项，**没有 `bash.exe`**：`git.exe`、`git-gui.exe`、`gitk.exe`、`git-lfs.exe`、`git-receive-pack.exe`、`git-upload-pack.exe`、`scalar.exe`、`tig.exe`、`aslr-manager.ps1`、`start-ssh-agent.cmd`、`start-ssh-pageant.cmd` |
| 直接敲 `bash` | `CommandNotFoundException`（PowerShell 原文："不是 cmdlet、函数、脚本文件或可运行程序"） |
| 用**全路径**跑 `22` 的断言脚本 | **13 通过 / 0 失败，exit=0** ✅ |

**为什么是"一半在 PATH"而不是"没装"**：`cmd` 里放的是 11 个**面向 Windows 命令行的包装器**，`bin` 与 `usr\bin` 里放的是**整个 MSYS2 工具链**（unix 工具数以百计）。Git for Windows 的安装器默认只把 `cmd` 加进 PATH，这是一个刻意的取舍——把 `usr\bin` 全加进去会与系统命令撞名（`find.exe` / `sort.exe` 一类）。（这条"为什么"是我据目录内容的推断，不是对 Git 官方意图的引证；但"PATH 里只有 `cmd`、而 `cmd` 里没有 bash"是实测。）

**结论**：`22 §4.1/§4.2` 交付的 `check-numeric-consistency.sh` / `check-no-corpus-files.sh` **本身是好的**，`22 §5` 声称的"13 通过 / 0 失败"我独立复现了；但**文档给的调用方式 `bash scripts/verify/check-numeric-consistency.sh` 在这台机器的普通终端里会失败**——因为 `bash.exe` 所在的 `D:\Git\bin` 不在 PATH。

**三种立刻可用的姿势（不改 PATH 也能跑）**

```powershell
# ① 全路径（最直接）
D:\Git\bin\bash.exe scripts/verify/check-numeric-consistency.sh

# ② 双击 D:\Git\git-bash.exe 开一个 Git Bash 窗口，在里面照 22 的写法敲 bash（那窗口的 PATH 里有 bash）

# ③ 把 D:\Git\bin 加进 PATH —— 但要记住：改完必须注销重登（或重开编辑器），见 README §5 的提示
```

> 这与委托方前几日踩的 "`mvn` 找不到" **是同一类坑**：工具装好了、目录不在 PATH。区别是这次坑埋在文档的执行指引里，踩的人是下一位照文档做的人。
>
> 另外：`22 §5` 那次"实跑通过"是在**另一个 shell 环境**里执行的，不能推出"用户在自己的终端里能跑"——**"在我这儿跑通了"与"照文档能跑通"不是同一件事**。这条已由 `21` 的 H4 与 `13 §13.6.1` 反复指出，此处是第三次同源。

**修法（在以上三种"姿势"之上做取舍）**

| 姿势 | 适合 | 代价 |
| :-: | --- | --- |
| ① 全路径 | 临时跑一次 | 换机器即失效，不适合当长期指引写进文档 |
| ② Git Bash 窗口 | 交互式调试 | **无法被脚本/门禁调用**——门禁必须是无人值守的 |
| ③ 加 `D:\Git\bin` 进 PATH | 一劳永逸地让"随手敲 `bash`"可用 | 与 `mvn` 那次同理，**改完必须注销重登**，否则新终端仍是旧环境快照 |
| **④（推荐，本节新增）在 `scripts/verify/` 下加 `*.cmd` / `*.ps1` 包装，内部调到全路径** | **门禁入口** | 不依赖任何人的 PATH、Windows 本地一键可跑——**与 §4.2 的"一键门禁"是同一件事，合并做** |

推荐 **③ + ④ 一起做**：③ 解决"手敲 `bash` 能用"，④ 解决"门禁不依赖环境"。只做 ③，则换一台机器、或者哪天 Git 换了安装目录，门禁又会静默失效。

> ⚠️ **加 PATH 时加 `D:\Git\bin`，不要加 `D:\Git\usr\bin`。** 实测：`D:\Git\bin` 只有 **3 个文件**（`bash.exe` / `git.exe` / `sh.exe`），零撞名；而 `D:\Git\usr\bin` 有 **364 个文件**，其中 **7 个与 `C:\Windows\System32` 精确撞名**——`find.exe`、`sort.exe`、`tar.exe`、`timeout.exe`、`hostname.exe`、`whoami.exe`、`expand.exe`。
>
> 危险的不是"多"，而是**同名**：批处理与构建脚本极常用 `timeout /t`、`find`、`sort`、`tar`，而这些 MSYS2 版本的参数语义与 Windows 版**不同**。一旦 PATH 顺序变化让它们胜出，症状是"某个 `.cmd` 在某台机器上行为不一样"，且极难归因。
>
> **追加到 PATH 尾部（不要前置）**：追加永远不会改变已有命令的解析路径，因此 `git` 仍走原来的 `D:\Git\cmd`，只新增 `bash` 与 `sh`。
