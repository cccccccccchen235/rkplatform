## 3. 两处后端修复

### 3.1 `StpInterface` 从未实现 → 管理端对任何人 403（实现漏项）

**设计明确要求**：[06-backend.md:148](06-backend.md) —— 「`rk-api` 提供 `StpInterfaceImpl` 实现，从 `sys_user.role` 返回角色，供 `@SaCheckRole("ADMIN")` 使用。」

**事实**：`server/` 里 `StpInterface` / `getRoleList` **全项目零命中**。Sa-Token 靠它回答"这个 loginId 有哪些角色"——没有它角色列表恒为空，`@SaCheckRole("ADMIN")` 对**任何人**都是 `403 + 1004`。

**处置**：按 `06` 点名的类名新增 `rk-api/…/config/StpInterfaceImpl.java`：
- `getRoleList` 从 `sys_user.role` 取（loginId 即 `sys_user.id`，由 `AuthController:69` 的 `StpUtil.login` 设定）
- **fail-closed**：解析失败一律返回空列表 → 403，不因异常放行
- 取不到用户（令牌比用户活得久）时**不抛异常**——把 `2005` 混进鉴权判定会让响应不可预测
- `getPermissionList` 恒空（本项目是角色制，无权限点）

**取证（双向）**：

| 方向 | 结果 |
| --- | --- |
| 管理员 `GET /admin/subjects` | `code=0`，20 条 ✅ |
| 管理员 `GET /admin/outline?subjectId=6` | `code=0`，13 条 ✅ |
| 管理员 `GET /admin/knowledge-points?subjectId=6` | `code=0`，**452 条** ✅ |
| **负向对照**：普通用户 `negctl_81217` 打同一路径 | **HTTP 403** ✅ |

> **这修正了 `24 §9.1` 的归因。** 它把 6 条行为验收**全部**归因于"没有管理员登录态"。实际上**即使凭据修好，管理端依然全 403**。"用一个根因解释所有症状"的代价：这个缺陷一直藏在凭据问题后面——`15`（P1 出入）与 `16`（P1 代码审查）两轮都没看见，因为那时从没跑过一次真实的 admin 调用。

### 3.2 客户端异常家族：3 种误用落进"系统内部错误"

**先复现，再修**（不是只修撞到的那一个）：

| # | 客户端误用 | 修复前 | 修复后 |
| :-: | --- | :-: | :-: |
| 1 | 路径不匹配 | 1003 | 1003 |
| 2 | **方法不支持**（`GET /admin/outline/6`） | **1000** ❌ | **1003** |
| 3 | **缺必填参数**（`/admin/outline` 不带 `subjectId`） | **1000** ❌ | **1001** |
| 4 | 参数类型错（`subjectId=abc`） | 1001 | 1001 |
| 5 | **请求体非法 JSON** | **1000** ❌ | **1001** |
| 6 | `Content-Type` 不支持 | 1000 | 1001 |
| 7 | `Accept` 只收 xml | 1000 **+ ERROR 堆栈** | 406，**不记 ERROR** |
| 8 | 正常调用 | 0 | 0 |
| — | **日志 ERROR 条数** | **1** | **0** ✅ |

**新增 4 个 handler**（`GlobalExceptionHandler`）：

| 异常 | 映射 | 字段名 |
| --- | :-: | --- |
| `HttpRequestMethodNotSupportedException` | **1003** | —（不新建码：从客户端视角"这个 URL + 这个方法"就是不存在；且不暴露"这里有别的方法可用"） |
| `MissingServletRequestParameterException` | 1001 | 取 `getParameterName()` |
| `HttpMessageNotReadableException` | 1001 | 固定 `body`（连 JSON 都没解析出来，无可归属字段） |
| `HttpMediaTypeNotSupportedException` | 1001 | 固定 `Content-Type` |
| `HttpMediaTypeNotAcceptableException` | **406**（裸，无响应体） | — |

**第 7 条要单独说明**：它是 `05 §5.1.1`「除 401/403 外一律 200」的**第三类例外，且无法避免**——响应体是 JSON，客户端的 `Accept` 明确拒绝它，统一响应体根本没有交付的可能。**但 ERROR 污染是可以避免的**，故显式给 406 且记 DEBUG。本项目的 SPA（axios 默认同时接受 `application/json`、`text/plain` 与通配符）不会触发它。

**为什么第 2 条不是罕见分支**：`GET /admin/outline/nodes` 会先匹配上 `/admin/outline/{id}` 这条只有 PUT/DELETE 的映射（`{id}` 取到 `nodes`），于是抛"方法不支持"。**任何段数相同的错误路径都可能走到这里。**

## 7. 本轮记录的错误：同族问题已累计 8 次，本轮新增 4 次

| # | 错误 | 性质 | 轮次 |
| :-: | --- | --- | --- |
| 1 | 用**被注入过的 shell** 去验证用户的 PATH，得出"`mvn` 正常" | 用无效环境得出有效结论 | 早于 `17` |
| 2 | `lastLoginAt` 用**区分大小写**的模式检索 → 假阴性，差点否定一个正确引用 | 假阴性 | `21` 的 H4 |
| 3 | 用 `LENGTH()`（**字节**）比 60（**字符**）→ 断言"不是 bcrypt" | 度量单位错 | 本轮 |
| 4 | `mysql -B` 的输出**转义**被当成存储值（靠字节级比对才避开） | 表示 ≠ 存储 | 本轮 |
| 5 | 测试脚本按"**调用没抛异常**"打 ✅，不按 `code` 判 → 把 `1000` 打成 ✅ | 判定依据错 | 本轮 |
| 6 | `Select-String` **默认不区分大小写** → 匹配到 `ErrorReportValve`，把栈尾当栈首 | 检索方式错 | 本轮 |
| 7 | javadoc 里 `{@code ... */* }` 的 **`*/` 提前终止注释块** → 一串"非法的字符" | 表示层边界 | 本轮 |
| 8 | PowerShell **双引号套双引号** → 脚本解析失败 | 表示层边界 | 本轮 |

**判据（写给下一个做核实的人）**：这个项目的技术栈横跨 **JS / Java / SQL / shell / 日志**五种表示层，每一层都有自己的"表示 → 存储/传输"转换。**凡是"数值或结论对不上预期"的判断，先问三句**：

1. **这是谁在表示它？**（字节数？字符数？批处理转义？日志大小写？）
2. **我的判定依据是什么？**（退出码？HTTP 状态？还是 `code` 字段？）
3. **这个方法会不会恒真/恒假？**（1 与 2 都是这么栽的）

第 3 问最容易被跳过：`22 §5` 立的规矩是"任何断言都必须先用一次人为制造漂移证明它会失败"，本轮把它用在了校验器上（5 种违规全部抓到），但**没用在自己的测试脚本上**——于是第 5 条发生了。
