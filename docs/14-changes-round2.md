## 2. 逐项落实

### G1 · 场次二 `PENDING` 时会话无终止路径（中高）

**性质**：A5（引入场次模型）与 B9（收紧历史列表过滤）**各自正确，叠加后产生的新缺陷**——单独看任一方都没有问题。

**落地**：

| 落点 | 内容 |
| --- | --- |
| [06](06-backend.md) §6.13 | 新增任务「**会话级滞留结算**」，每 30 分钟：会话 `IN_PROGRESS` 且当前场次 `PENDING`，且**上一场次的 `finished_at` 早于 `NOW() - 6h`** → 按 05 用例 23 已定语义自动交卷（未作答场次一并 `FINISHED`，成绩页标 `answered = false`） |
| [06](06-backend.md) §6.13 | 补一段「为什么必须有这个任务」的决策说明，并顺带修正「过期数据清理」的表述（`ABANDONED` 只由用户主动放弃产生，自动路径不产生，该任务此前近乎空转） |
| [04](04-database.md) §4.8.3 | 新增两个配置键：`task.enabled.session.stale`、`exam.session.stale.hours` |
| [05](05-api.md) 用例 17 | 明确 **`IN_PROGRESS` 在任何取值下都不返回是有意设计**，并禁止后人为了"找回未完成考试"把它加进列表 |
| [07](07-frontend.md) §7.4 | 明确 `4003` 对话框是窗口期内**唯一**的找回入口，必须显示 `sessionId`；窗口期结束后由服务端自动处理，前端无需额外动作 |

**采用的两个设计要点（均来自 13，判断正确）**：① 判据用 `finished_at` 而非 `updated_at`（`GET /exams/{id}` 是读操作不写库，用活动时间会漏判）；② 选"自动交卷"而非"自动放弃"（保留场次一已考出的成绩，且完全复用 05 用例 23 既有语义，不引入新状态）。

### G2 · `exam_session_section` 漏快照 `sitting_no` 与 `support_status`（高）

**落地**（与 G3 合并为一次 DDL 变更，共改 04 的 3 处）：

```sql
-- exam_session_section 新增两列
sitting_no     TINYINT NOT NULL COMMENT '所属场次（1/2）；创建会话时从 exam_paper_section 快照',
support_status VARCHAR(16) NOT NULL DEFAULT 'SUPPORTED' COMMENT 'SUPPORTED / NOT_SUPPORTED，快照自模板',
```

同时在 [06](06-backend.md) §6.9.3 补了「**快照写入**」段，明确：创建会话时**从 `exam_paper_section` 复制**结构字段，**不允许 JOIN 回模板表取值**。

> **为什么不能 JOIN 替**：13 §13.3.3 指出的这一点是对的——模板是可被管理员修正的（ADR-04 把"允许修正配置错误"明列为模板驱动的收益之一），一旦修正，历史成绩的场次归属与"无法模拟"标记就会随之漂移，恰好破坏快照要保的可复现性。
> 对照 `exam_session_item` **有** `section_no`，可见 `exam_session_section` 缺的是两列而非"有意不存"，**属漏列**。

### G3 · A6 未真正闭合（中高）

**落地**：04 的 4 处 `INT NULL` → `INT NOT NULL`（`exam_paper_section` 2 处、`exam_session_section` 2 处），并在注释里写明**为什么这里用 DDL 强制而 B7 不用**：

> B7 保持可空有正当理由（`source_type` 各取值所需字段本就不同）；A6 没有——分节不存在"不需要时长约束"的场景，`Σ(duration_min) ≤ sitting.total_duration ≤ Σ(duration_max)` 是硬不变式。**建库期的 `NOT NULL` 是唯一能抓住漏填的机制**：P1 写 `init-data.sql` 时漏填不会报错，后果不是报错而是**静默失效**（门槛算不出来，该分节永远退不出去或 NPE）。

13 指出的"加重情节"成立且已消除：04 §4.8.2 目前只给蓝图注释、20 科目的完整 `INSERT` 属 P1 交付物，所以现在正是加 `NOT NULL` 的最低成本窗口（P5 之后要写数据迁移并回填历史会话）。

同时在 [10](10-roadmap.md) §10.3 的 P1 验收补了一条可执行断言：

```sql
SELECT COUNT(*) FROM exam_paper_section WHERE duration_min IS NULL OR duration_max IS NULL;  -- 必须为 0
```

### G4 · 两个 `remaining_sec` 双写无优先级（低）

**落地**：[06](06-backend.md) §6.9.1 的「计时权威」块补一段：`exam_session.remaining_sec` 是**当前场次那个值的镜像**，只在场次开始 / 作答写入 / 场次结束时随 `exam_session_sitting` 同步更新、**不独立演进**；**任何读取一律以 `exam_session_sitting` 为准**。即使镜像落后也不会污染判定——因为它从不参与判定。

### G5 · 分节状态机无权威定义处（低）

**落地**：[02](02-domain-model.md) 新增 **§2.5.6 分节状态**（`PENDING` / `IN_PROGRESS` / `FINISHED` / `SKIPPED`，含各状态的进入条件）。04 中该列注释改为 `权威定义见 02 §2.5.6`。

> 02 是全项目既定的权威定义处（08 §8.4 自己写着"以 02 · 2.2.2 的字段定义为唯一来源"），而 02 有会话状态机（§2.5.2）、场次状态机（§2.5.5），**唯独缺分节**——补齐后三条状态机同处一源。

> ⚠️ **一处有意偏离 13 的字面要求**
> 13 §13.8.2 要求"文档篇数统一为 **14**（README + `01`~`13`）"。本轮**没有采用这个数字**，改为「README + `docs/01`~`docs/14`」并把 P0 验收①写成自维护表述。
> 原因：本轮记录的落地文档是 `docs/14`，一旦它存在，"14"这个数字**立刻过期**（实际为 README + 01~14 共 15 个文件）。沿用 13 的数字等于在同一处制造一个它正要消灭的缺陷。
> 做法上遵循了 G9 自己的原则——**"只有一个出处，其余处引用而非复写"**；对无法避免复写的地方（P1 验收命令里的表数量）则用 CI 断言兜底。**表数量 27 是设计事实，保留为数字**；文档篇数是会随文档链增长的易变值，因此不写死。

13 §13.6.1 的方法论结论（**自查表一旦出现假阳性，其余所有 ✅ 都要重新打折**）已被采纳：本文档 §4 的自查表采用"可判定、可复现"的表述，且**每一项都是跑检索得出的**，不按印象勾选。

### G8 · 06 一处表述过时（低）

**落地**：[06](06-backend.md) §6.5 尾句「该标志位的持久化列需 `sys_user` 同步补齐」删除，改为「持久化列为 `sys_user.must_change_password`（已存在于 04）」。

### G9 · P0 验收标准缺「数值一致性」（中）

**落地**：[10](10-roadmap.md) §10.2 新增第 6 条验收项（**数值一致性**：同一事实只有一个出处，其余处引用而非复写；复写不可避免的加 CI 断言），并附 `> 决策与理由` 说明它是**流程级**修正——两轮共 47 条发现里，数值/计数漂移占 6 条（13%），成因都是"同一个数字被两个文档各写了一遍，然后两边各自演进"；而 P0 原先 5 条验收项检查的全是结构一致性，**所以 P0 能"通过"验收却同时存在三组互相矛盾的容量数字**。

## 3. 结构性变更汇总

本轮**没有结构性变更**（不新增表、不新增接口）。全部改动是：**3 列新增 + 4 列非空化 + 1 个新定时任务 + 2 个配置键 + 1 节状态机定义 + 7 处计数回填 + 6 处表述澄清**。

| 类别 | 数量 | 对象 |
| --- | --- | --- |
| 新增列 | 2 | `exam_session_section.sitting_no`、`exam_session_section.support_status`（G2） |
| 列约束收紧 | 4 | `exam_paper_section.duration_min/max`、`exam_session_section.duration_min/max` → `NOT NULL`（G3） |
| 新增定时任务 | 1 | 会话级滞留结算，每 30 分钟（G1） |
| 新增配置键 | 2 | `task.enabled.session.stale`、`exam.session.stale.hours`（G1） |
| 新增权威定义 | 1 | 02 §2.5.6 分节状态（G5） |
| 计数/表述回填 | 13 | G4 / G6（7 处）/ G8（1 处）+ 05、06、07 的行为澄清 |

**表数量不变：27 张**（只加列，不加表）。
